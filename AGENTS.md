# volonterski — правила работы агента

Репозиторий: roblencheg/volonterski. Основная ветка: main. Адрес сайта: https://volonterski.ru.
Перед изменениями прочитай этот файл и docs/PUBLISHING.md.

## Публикация из чата
- «Пиши статью» или «Опубликуй на volonterski» означает: оформить результат текущего обсуждения в самостоятельную статью, добавить необходимые материалы и закоммитить в main. Авторизация относится только к выбранному материалу.
- «Сохрани черновик» означает draft: true. Файл черновика публичен в GitHub, хотя в сборку сайта не попадает. Не используй это для конфиденциальных данных.
- «Обнови статью» означает найти существующую, сохранить id/URL и исходную дату, установить updated.
- Если в чате нет доступа на запись — явно сообщи об этом. Не выдавай подготовленный текст за опубликованный материал.

## Редакционные правила
Статьи о проектах пользователя пиши от его лица как автора и владельца: что я сделал, как реализовал и какие решения выбрал. Не используй тон стороннего обзора чужого репозитория. Не выдумывай личные истории, мотивы, испытания и результаты; авторская подача не заменяет проверку фактов.
Не добавляй имя автора или персональные подписи в интерфейс, метаданные, RSS и публикации без прямого запроса пользователя.
Пиши по-русски, конкретно и без выдуманных результатов. Не добавляй лозунги, декоративные подписи, шаблонные вступления и статьи-заполнители. Интерфейс использует прямые названия действий и объектов. Предпочитай структуру: задача, ограничения, решение, результат, материалы. Не добавляй разделы ради шаблона. Сохраняй важные команды полностью. Различай проверенные факты и гипотезы. Не публикуй токены, пароли, персональные или внутренние корпоративные данные, если пользователь явно не выбрал их для публикации и это допустимо. Не извлекай другие чаты и файлы без связи с запросом.

## Технические правила
- Статьи: src/content/articles/<latin-kebab-case>.md. Не меняй адрес опубликованной статьи.
- Вложения: public/files/<article-id>/. Не используй временные sandbox-ссылки или приватные ссылки ChatGPT.
- Сначала прочитай актуальную версию/ветку. Сохраняй чужие изменения. Используй один атомарный коммит для статьи и вложений.
- Проверка: npm ci; npm run build; npm run verify. Не коммить node_modules, dist, .astro.
- Изменение статьи автоматически запускает Actions. После коммита проверь build/deploy и верни адрес статьи. Если деплой не подтверждён, скажи это явно.
- Не добавляй зависимости, сервер или CMS для публикации обычной статьи.
