# Поиск и распространение

## Работает без внешних аккаунтов

- Сборка создаёт PNG 1200×630 для каждой опубликованной статьи и главной страницы. В head доступны Open Graph и Twitter Card.
- Статьи содержат BlogPosting JSON-LD, даты, canonical и ссылки «По теме». Имя автора не добавляется.
- Sitemap и RSS обновляются при сборке. Черновики не попадают в выдаваемые файлы.
- Workflow `Notify search engines` запускается после успешного деплоя, вручную и ежедневно в 10:17 по Новосибирску. Он проверяет публичный HTTPS-каталог и соответствие опубликованного коммита. Затем отправляет в IndexNow только изменённые URL и удаления. Состояние подтверждённых отправок хранится в GitHub Actions Cache. Если кэш удалён, возможна повторная отправка доступных страниц.
- HTTP 200/202 от IndexNow означает приём уведомления, а не гарантированную индексацию. При недоступном домене/сертификате/ошибке сервиса workflow показывает ошибку и повторяет попытку в следующий запуск. Деплой сайта от результата уведомлений не зависит.
- `Watch project releases` ежедневно в 11:47 по Новосибирску проверяет стабильные релизы трёх проектов из config/project-sources.json. Новые релизы создают редакционные файлы в ветке automation/release-updates и draft PR. Автослияния и автоматического переписывания статьи нет. Если настройка GitHub запрещает создание PR через Actions, файлы останутся в ветке и артефакте workflow.

IndexNow-ключ в config/promotion.json публичный: файл проверки обязан быть доступен на сайте. Это не пароль. Уведомления идут через общий endpoint, без внешнего платного сервиса.

## Редакционный цикл

После проверки новой версии обновить существующую статью (сохранив slug и date), установить updated и изменить reviewedRelease в config/project-sources.json. Заметки релиза — входные данные для редактора, а не готовый проверенный текст от лица автора. Скрипт не заявляет об испытаниях автомобиля.

## Поисковые кабинеты: доступ пока не предоставлен

Google Search Console, Яндекс Вебмастер и Bing Webmaster Tools требуют отдельной авторизации и подтверждения владения сайтом. Они не считаются подключёнными только потому, что на сайте есть sitemap.

Подготовлена поддержка HTML-подтверждения. После получения кодов в соответствующих кабинетах можно задать repository variables:

- GOOGLE_SITE_VERIFICATION
- YANDEX_SITE_VERIFICATION
- BING_SITE_VERIFICATION

Следующая сборка добавит соответствующие meta-теги. Затем завершить проверку в кабинете и отправить https://volonterski.ru/sitemap.xml.

## Каналы публикации

Telegram и DEV.to не подключены: не предоставлены целевой канал, аккаунт и токены. Автоматических отправок туда нет. RSS уже доступен на /rss.xml и может быть использован внешними читателями или сервисами после их подключения. LLM API не используется, платных подписок для работающей части нет.

## Проверка

```sh
npm ci
npm run build
npm run verify
node --test tests/promotion.test.mjs
```

Сценарии уведомлений тестируются без внешних запросов: повторная отправка неизменённых URL, обработка удалений, защита от уведомления о старом деплое или чужом домене. Проверки релизов не меняют публичную коллекцию статей.
