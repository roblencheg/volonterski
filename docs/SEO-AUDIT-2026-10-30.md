## Остаётся проверить после деплоя

1. **HTTP и домен**: `https://volonterski.ru/` отдаёт 200, HTTPS валиден, `http://` и `www` переадресуют к единому HTTPS-домену; все URL sitemap отвечают 200.
2. **Поисковые кабинеты**: подтвердить владение `volonterski.ru` в Google Search Console и Яндекс Вебмастере, отправить `https://volonterski.ru/sitemap.xml` и проверить URL Inspection. Коды можно передать в repository variables `GOOGLE_SITE_VERIFICATION`, `YANDEX_SITE_VERIFICATION`, `BING_SITE_VERIFICATION`.
3. **Реальная индексация**: наблюдать Indexed/Excluded, Coverage, причины исключения и фактические поисковые запросы. Проверка `site:volonterski.ru` полезна, но не заменяет Search Console.
4. **Скорость**: замерить мобильные Core Web Vitals через PageSpeed Insights и CrUX, исправлять подтверждённые узкие места, не жертвовать читабельностью.
5. **Сниппеты**: проверить Schema Markup Validator/Google Rich Results Test и фактический вид результатов Google/Яндекса после переобхода.
6. **Внешние ссылки**: добавить естественные ссылки на конкретные статьи из README соответствующих публичных репозиториев и тематических материалов. Не использовать сети искусственных ссылок, покупку трафика и автоспам.
7. **Контент**: дополнять практические кейсы проверенными командами, версиями, фотографиями/скриншотами и результатами; периодически актуализировать даты только после реальных изменений. Не создавать массовые страницы «под ключевые слова» без пользы.

## Ограничения

Sitemap, IndexNow и структурированные данные помогают обнаруживать и понимать страницы, но не гарантируют индексации или высоких позиций. IndexNow не является заменой отправке sitemap в Google Search Console. Для сайта на GitHub Pages ограничения redirects/HTTP-заголовков требуют отдельного теста на опубликованном домене.
