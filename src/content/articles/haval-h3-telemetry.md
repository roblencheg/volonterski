[H3 Telemetry](https://github.com/roblencheg/haval_h3_telemetry) — Android-приложение для штатного головного устройства Haval H3. Оно читает доступные автомобильные сигналы и выводит их на дополнительный дисплей приборной панели.

Для этой задачи не нужны Home Assistant или облачный аккаунт. Приложение обращается к системному сервису ГУ `gwm_adapter` и показывает данные локально.

Важная разница версий на **29 октября 2026 года**: в текущей ветке исходников указана **1.7.0**, а в GitHub Releases опубликован APK **1.2.1**. Ниже разобран текущий код. Нельзя считать, что все описанные настройки уже входят в доступный APK.

## Где приложение проверено

Документация указывает конкретную конфигурацию: **Haval H3, штатная ГУ на Android 9, код проекта 203, приборная панель 1920 × 720**.

Для чтения данных нужен системный интерфейс `gwm_adapter` и разрешение `com.gwm.android.adapter.permission.GET_DATA`. Обычного Android-смартфона для работы приложения недостаточно: на нём нет этого сервиса и автомобильного дополнительного дисплея.

Совместимость с другой прошивкой или моделью требует отдельной проверки. Совпадение марки автомобиля само по себе ничего не гарантирует.

## Три основных показателя

По умолчанию включены остаток топлива, температура охлаждающей жидкости и напряжение 12-вольтового аккумулятора. У каждого показателя можно отдельно изменить видимость, координаты и размер текста.

В текущем коде предусмотрены дополнительные сигналы: температура салона, пробег, расход, состояние двигателя, данные коробки передач и TPMS, а также текущая дата. Наличие пункта в настройках означает, что приложение умеет его запросить и отобразить. Это не подтверждение того, что конкретная ГУ возвращает осмысленное значение. Отсутствующий показатель отображается прочерком.

### Как получаются литры топлива

Входной сигнал содержит процент остатка. Приложение переводит его в литры с фиксированной константой **55 л**:

```text
литры = процент × 55 / 100
```

Это расчёт приложения, а не прямое измерение объёма топлива. Например, при 40% получится 22 л. Константа взята из кода проекта; её нельзя переносить на другой автомобиль как универсальную характеристику бака.

[GWM RU](/articles/gwm-ru-home-assistant/) использует другую схему: получает литры из облака и рассчитывает проценты по переданной облаком ёмкости. Поэтому показания двух проектов могут не совпадать.

## Как устроен вывод

`GwmAdapterClient` подключается к Android Binder-сервису, подписывается на изменения и дополнительно опрашивает набор сигналов раз в **2 секунды**. При потере соединения предусмотрено повторное подключение.

`TelemetryService` поддерживает работу фонового сервиса, принимает обновления и запускает `ClusterActivity` на дополнительном дисплее. В первую очередь выбирается дисплей с ID `2`; если его нет — другой дисплей, отличный от основного. Окно рассчитано на область 1920 × 720.

`ClusterActivity` создаёт прозрачное окно с текстовыми показателями. Оно не принимает касания. Положение элементов и размер шрифта сохраняются в настройках приложения; текущий код допускает размер текста от 18 до 48 пикселей.

В манифесте нет разрешения `INTERNET`. Рассмотренный код работает с локальным системным сервисом, а не отправляет телеметрию на внешний сервер.

## APK и запуск

Готовый опубликованный файл находится в [релизе 1.2.1](https://github.com/roblencheg/haval_h3_telemetry/releases/tag/v1.2.1). После подключения к своей ГУ через уже настроенный ADB его можно установить или обновить:

```powershell
adb install -r .\Haval-H3-Telemetry-v1.2.1-release.apk
adb shell monkey -p app.havalh3.telemetry -c android.intent.category.LAUNCHER 1
```

Эти команды относятся именно к APK 1.2.1. Для версии 1.7.0 потребуется сборка текущих исходников либо соответствующий подписанный релиз, когда он будет опубликован. Инструкция установки не означает, что совместимость с вашей ГУ уже проверена.

Для debug-сборки в README указаны JDK 17, Android SDK 35 и Gradle 8.9:

```bash
gradle --no-daemon assembleDebug
```

Результат — `app/build/outputs/apk/debug/app-debug.apk`. Debug-подпись может отличаться от подписи установленного релизного приложения; её нельзя считать обычным обновлением с сохранением настроек.

## Автозагрузка и диагностика

В исходниках 1.7.0 автозагрузка включена по умолчанию. Обрабатываются обычная, ранняя и быстрая загрузка Android, а также обновление пакета. Если приборный дисплей ещё недоступен, приложение повторяет попытки запуска с интервалом 5 секунд, до 120 попыток.

На главном экране предусмотрены команды «Показать» и «Скрыть», переключение автозагрузки и настройка отдельных показателей.

Для проверки подключения и загрузки используются теги журнала:

```powershell
adb logcat -d |
  Select-String "H3GwmAdapter|H3TelemetryService|H3TelemetryBoot|SecurityException"
```

Обновление прошивки ГУ может изменить системный интерфейс или конфигурацию дисплеев. Первую настройку положения текста и проверку новой версии проводите на неподвижном автомобиле: показатели не должны перекрывать штатные предупреждения.
