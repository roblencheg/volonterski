# Собственная аналитика volonterski.ru

Полностью самостоятельный backend Node.js 24 + встроенный SQLite, без внешнего SaaS и SDK. Сайт остаётся на GitHub Pages; сервис разворачивается отдельно на собственном сервере под HTTPS-адресом, например `https://stats.volonterski.ru`.

## Запуск

```bash
cd analytics
cp .env.example .env
# Заменить ADMIN_PASSWORD (16+ символов) и SESSION_SECRET (32+ случайных символа)
chmod 600 .env
docker compose -f compose.yaml up -d --build
docker compose -f compose.yaml ps
curl -fsS http://127.0.0.1:3090/health
```

Поднимите HTTPS reverse proxy с маршрутизацией `https://stats.volonterski.ru` к `http://127.0.0.1:3090`. Docker по умолчанию публикует порт **только на loopback**, поэтому proxy на другом сервере требует отдельной защищённой сетевой настройки. Не открывайте порт без TLS в интернет. Рекомендуется ограничить доступ к `/dashboard` и `/api/report` ещё и на reverse proxy (по IP/VPN). Публичный путь `/collect` нужен всем посетителям сайта.

Далее добавьте GitHub Actions repository variable `ANALYTICS_ENDPOINT` со значением `https://stats.volonterski.ru/collect` и запустите workflow Deploy. Переменная публичная, токенов в frontend нет. При пустой переменной сбор статистики **выключен**: это безопасно до развёртывания сервиса.

Панель: `https://stats.volonterski.ru/dashboard`, браузер запросит `ADMIN_USER` / `ADMIN_PASSWORD`. Запросы к `/api/report` также закрыты HTTP Basic Auth. Удалённый API управления данными не предусмотрен.

## Метрики

- Просмотры страниц, сессии по UTC-дням, динамика 7/30/90 дней.
- Рейтинг статей и источников по hostname или `utm_source`.
- Дочитывания 75% и 100%, переходы в GitHub, скачивания, копирование кода, использование поиска и распространение ссылок.

Сессия идентифицируется случайным идентификатором вкладки (sessionStorage), хешированным на сервере с секретом и текущим днём. Хеши удаляются после двух дней, итоговые агрегаты остаются. **Сессия не равна уникальному человеку**. В базе нет IP, user-agent, полного referrer, содержимого поисковых запросов и сырых URL с query-параметрами. IP может временно использоваться в памяти для ограничения частоты запросов, но не записывается на диск.

События могут быть заблокированы расширениями браузера. `Origin` проверяется, но не является защитой от подделки запросов внешним скриптом или curl. На публичный endpoint применено примитивное ограничение 300 запросов/мин на TCP-адрес; при большом трафике нужен rate limit на прокси. Не интерпретируйте эти данные как абсолютную истину.

## Резервные копии

База в Docker volume `analytics_data`. Создавайте резервную копию с остановленным контейнером либо используйте SQLite backup API через отдельный процесс. `docker compose down -v` удаляет данные без возможности восстановить их из GitHub.

Для локальных тестов сервера: `node --test analytics/server.test.mjs` с Node.js 24. GitHub Actions выполняет тест автоматически.

## Разграничение систем

Clarity остаётся отдельной опциональной интеграцией для карт кликов и записей. Собственный backend не требует Clarity и Umami. Чужие счётчики можно отключить, если больше не нужны.
